# 合成曲评估：三首不同风格的可复现基准

上一篇 `06-model-benchmarks.md` 评估的是**歌词**（同一首真歌，换 ASR 模型）。这一篇评估的是**整条分析链路**：拍号、BPM、调性、和弦、段落。真歌没有标准答案，所以用「自己合成、自己知道正确答案」的曲目来量。

> **一句话结论**：三条合成曲综合得分 **85.1 / 100**（修复前 72.7）。拍号 / BPM / 调性 / 和弦四项全部满分，**唯一失分项是段落边界**——而段落这一项在这套基准里不可信，见第 5 节。

---

## 1. 为什么要合成曲

真歌（`小林未郁、HOYO-MiX - 下一站 Beyond This Station.flac`）能验证「跑得通、听得过去」，但不能验证「对不对」：没有人给过这首曲子的和弦谱、调性、BPM 标准答案。用真实曲目做评估，只能靠耳朵和主观判断，改一个参数后无法判断是变好还是变坏。

合成曲解决这个问题：

- **正确答案是自己写死的**——`aitsm/testsupport/synth_song.py` 里的 `Profile` 同时是合成配方和 ground truth，不可能与实现分叉。
- **完全确定性**——不依赖随机数种子、不依赖模型、不依赖网络，任何人任何时候跑出来的结果都一样。
- **可重跑对比**——改一行算法，重跑一次，得分直接可比。

代价是**它只能评估「这类信号处理对不对」，不能评估「音乐好不好听」**，也绝不能拿来验证歌词与旋律转谱。这条限制在下面第 5 节展开。

## 2. 三首曲目的设计意图

| profile | 曲风 | BPM | 拍号 | 调性 | 和弦进行 | 人声 | 想压测什么 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `waltz` | 慢三拍民谣 | 96 | **3/4** | C 大调 | C–Am–F–G | 有 | 非 4/4 拍号；慢速下拍点稀疏；三和弦纯度 |
| `rock` | 快速摇滚 | 138 | 4/4 | E 大调（4 个升号） | E–B–C#m–A | 有 | 快速度下 BPM 精度；强鼓点对和弦识别的干扰；升号调 |
| `instrumental` | 纯伴奏流行 | 104 | 4/4 | G 大调 | G–D–Em–C | **无** | 降级路径：没有人声时必须不崩、不编造歌词、仍输出可弹的谱 |

三首覆盖了弹唱谱最常见的三种形态：三拍子民谣、四拍子快歌、纯伴奏。`instrumental` 是特意加的「负向用例」——ASR 在纯音乐上很容易幻觉出歌词，这一首专门用来保证「宁可没有歌词，也不能有假歌词」。

合成方式：saw 波前 8 个谐波 + ADSR 包络做和弦/贝斯/主旋律，底鼓/军鼓/踩镲用噪声与正弦脉冲。**这不是真实乐器音色**，谐波结构与真实录音差异很大，所以它能测算法，不能测模型泛化。

## 3. 评分口径

`aitsm/testsupport/evaluate.py`，五个维度加权：

| 维度 | 权重 | 判定方式 |
| --- | --- | --- |
| BPM | 0.15 | 误差 < 2% 记满分，否则 0 |
| 拍号 | 0.10 | 分子分母都相同记满分 |
| 调性 | 0.15 | 主音+调式都相同记满分；只对**关系大小调**记一半 |
| 和弦 | 0.40 | 采样命中率（精确 / 含根音两档，评分用精确） |
| 段落 | 0.20 | 段落边界命中率 |

**和弦采样方式很关键**：在每个真值和弦区间**内部均匀取点**，并跳过两端 `EDGE_MARGIN = 0.12s`。

早期版本用的是「每 0.25s 固定网格采样」，把识别结果 25ms 的边界抖动误判成整段和弦错误，得出的结论是「识别系统性晚了一整小节」——完全错误的方向。改成区间内采样 + 跳过边界后，同一个算法的得分直接提高约 10 分。这是文档里最值得记住的一条教训：**评估器的 bug 会伪装成算法的 bug，而且方向可以完全相反**。

## 4. 结果

```
waltz        96.0 → 96.0 (0.0%)   3/4 ✓   C major ✓   和弦 100%   段落 40.0%   88.0
rock        138.0 → 138.0 (0.0%)  4/4 ✓   E major ✓   和弦 100%   段落 16.7%   83.3
instrumental 104.0 → 104.0 (0.0%) 4/4 ✓   G major ✓   和弦 100%   段落 20.0%   84.0
─────────────────────────────────────────────────────────────────────────────
平均                                                                        85.1
```

BPM 误差全部 **0.0%**，不是「运气好」：`fit_beat_grid` 用最小二乘拟合 `t = offset + k·period`，把 hop 量化带来的 23ms 系统性偏差消掉了。在此之前 `rock` 的 138 会被测成 136。

### 修复前的 72.7 分是怎么来的

| 问题 | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 6/8 误判 | `waltz` 的 3/4 被认成 6/8 | 两路打分用**绝对幅度**，6 拍候选只是 3 拍的抽样，靠「样本更多」白赢 | 两路各自 z 标准化后 0.45/0.55 融合；6/8 不给先验；硬规则：top1=6 且拍间隔 ≥0.40s（即 <50BPM 的八分拍，不合理）→ 降级为 3 |
| BPM 系统性偏差 | 138 → 136 | 用「拍间隔中位数」，把 hop 量化误差变成速度误差 | `fit_beat_grid` 最小二乘拟合，残差小则拍点吸附网格，大则只修 BPM |
| 斜杠和弦误判 | `instrumental` 的 C 小节被认成 `C/E` | 低音能量让转位和弦得分更高 | 低音主导音惩罚 `_SLASH_ROOT_PENALTY=0.16` + 偏好边际 0.10（分差 <0.10 取普通三和弦） |
| 三和弦被判成七和弦 | `waltz` 的 Am 小节被认成 Fmaj7（0.459 vs 0.458） | 七和弦惩罚太轻，邻小节 F 的谐波渗漏就够翻盘 | `COMPLEXITY_PENALTY` 里 7/maj7/m7 从 0.035~0.045 提到 **0.07~0.075** |

最后一条值得单独记住：**七和弦惩罚加重的理由是「四个音里只要一个音是渗漏能量，三和弦就会被误判成七和弦」，而不只是「弹唱谱偏好简单和弦」**。前者是物理原因，后者只是产品口味；只有前者能保证对真歌也是改进。

修复后真歌回归没有退化，反而略升：`quality` 0.804 → **0.829**，色彩和弦从一堆 `sus/maj7` 收敛到只剩 `Asus2`、`C#m7b5` 两个。

## 5. 这套基准能说明什么、不能说明什么

**能用来说明的：**

- 拍号判定、BPM 估计、调性判定、和弦序列这四项算法逻辑正确。
- 改动这些算法时的**回归防护**——现在 `pytest` 里 5 条相关用例（`fit_beat_grid`、6/8 降级/保留、和弦循环周期、uniform 判定）就是从这轮评估里长出来的。
- 降级路径正确：`instrumental` 全程无人声也不崩、不伪造歌词。

**不能用来衡量的（重要）：**

1. **段落边界命中率完全不可信，请不要看这个数字。** 合成曲的「段落」只是配方里重复几次和弦进行，同一段 intro 和 verse 的**和弦、配器、音色完全相同**，声学上根本没有段落切换的特征。任何段落检测算法在这种输入上都不可能对——`waltz` 40%、`rock` 16.7%、`instrumental` 20% 反映的是**基准本身没有信息**，不是算法差。段落检测请以真歌（12 段、含 `structure.coarse` 告警那条路径）为准。
   - 因此 85.1 这个综合分**被段落项系统性拉低了约 16 分**（0.20 × (1 − ~0.2)）。如果去掉段落项重新归一，三项真实反映能力的维度接近满分。
2. **不能评估歌词。** 合成人声是正弦波，ASR 在上面只会幻觉。歌词质量看 `06-model-benchmarks.md` 的 CER。
3. **不能评估旋律转谱。** 合成旋律音色过于干净，真实人声的颤音、滑音、气声一个都没有，得分会虚高。
4. **不能评估音色泛化。** 谐波结构是合成的，真实录音的乐器混响、房间、压缩全都不在。

**结论：把 85.1 理解成「信号层四项全对 + 段落项不可测」，不要理解成「产品完成度 85%」。** 用户能感知的弹唱谱质量，最终仍以真歌 + 人工试弹为准（见 `05-acceptance.md`）。

## 6. 怎么复现

```bash
# 合成三首曲子（写入 work/synth/{waltz,rock,instrumental}.wav + *.groundtruth.json）
python -m aitsm.testsupport.synth_song --out work/synth

# 跑分析（每首约 30-60s，CPU）
for p in waltz rock instrumental; do
  AITSM_SKIP_ASR=1 python -m aitsm.cli generate "work/synth/$p.wav" \
      --out "work/synth/$p" --no-separate
done

# 评估
python -m aitsm.testsupport.evaluate --all work/synth
```

`AITSM_SKIP_ASR=1` 是必须的：合成人声跑 ASR 只会浪费时间并产生幻觉歌词，对评估这四个维度没有贡献。注意 `--no-lyrics` 现在已经会正确跳过 ASR（`aitsm/service.py` 的 `_normalize_options`），两种写法都可以。

## 7. 后续可以怎么加强

按性价比排序：

1. **加混响与力度动态**——现在的合成曲是干声加固定力度，真实录音的混响会糊掉和弦边界，这是和弦识别最大的现实压力，值得加。
2. **加真实乐器采样**——用 sfz/soundfont 渲染，比 saw 合成更接近真实谐波，能测出更多问题。
3. **加段落基准**——在合成曲里真正做出配器差异（intro 只有钢琴、verse 加鼓、chorus 全编制 + 提高音量），段落项才有意义；这需要改 `synth_song.py` 的 `mix`，让它按段落变化。
4. **加「跨拍号和弦变化」用例**——目前进展都是每小节一个和弦，没有测「一小节两个和弦」「两小节一个和弦」，而这两种在流行歌里非常常见。

第 3 项和第 4 项加起来，才能把「和弦密度」这类参数（见 `04-known-issues.md`）变成可量化的取舍，而不是靠耳朵调。
