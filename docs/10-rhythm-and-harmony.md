# 节奏量化与和声证据增强

这一轮改动来自一个很具体的抱怨：网页上的谱子「能看」，但**节奏不规整、和弦置信度只有 0.57**。
置信度低不是打分脚本的问题，而是证据弱——两处证据弱得很具体：

1. **旋律的音符边界是拍出来的，不是「记谱上说得出口的」**。原始转换里 37% 的音符时值不等于任何一种
   合法音符形状（比如 0.138 拍），导出时只能拆成连音或者硬吸到十六分音符，听感上「节奏飘」。
2. **和弦只用「折叠到 12 个音级后的平均能量」判断**，人声旋律和低频鼓点都算进候选和弦里，
   三和弦经常因为多出来的一点能量被判成七和弦。

四项改动按这两个问题来：节奏侧两项（HMM 量化、pyin 前带通 + F0 平滑），和声侧两项
（谐波加权 chroma、chord 序列平滑），附带把歌词时间戳降级为软锚点。

---

## 1. 节奏量化：HMM 网格量化替代就近吸附

`aitsm/pipeline/quantize.py` 新增 `quantize_melody_events()`，用一阶 HMM 在「1/4 拍网格」上解码：

- **状态** = 音符的（起音格位, 时值格数），时值只允许 `1/2/3/4/6/8/12/16` 步（十六分到全音符含附点）；
- **发射代价** = 原始起音与网格点的距离 + `duration_cost`（非法时值给很大代价）；
- **转移代价** = `metrical_strength` 对「在弱拍位置放长音」的惩罚；
- **和弦变化点当锚点**：和弦换了的那个网格点，附近音符起音奖励对齐（权重 0.12）。

产物：所有音符时值都是可记谱值，且**逐小节求和等于拍号**。

一个必须记住的坑：**验证「可记谱」不能用全局 BPM 换算**。实际拍间隔逐拍有 ±8% 波动
（0.60~0.65 s），用全局平均拍长把 1/4 拍算成 0.138 拍，会把正确结果报成错误。
必须走 `aitsm.score.arrange._BeatGrid` 的分段线性映射。这个错误我先犯了一次，
评估表先给出「94% 可记谱」的假象，修正度量后真实数字才出来。

## 2. 旋律预处理：前带通 + F0 平滑

`aitsm/pipeline/melody.py`：

- 带通滤波 65–1200 Hz 再送 pyin（默认开，`AITSM_F0_BANDPASS=0` 关闭）；
- F0 后处理：中值滤波去除单帧跳变、对 <2 帧的短音并入邻音（`AITSM_F0_SMOOTH=0` 关闭）；
- 音域归位保持原逻辑（`AITSM_MELODY_LOW_MIDI` / `AITSM_MELODY_HIGH_MIDI` 可调）。

## 3. 和弦：谐波加权 chroma + 序列平滑

`aitsm/pipeline/chords.py`：

- `_harmonic_chroma()`：对每个音级，按「它的基频落在哪个八度」加权求和，权重
  `_HARMONIC_OCTAVE_WEIGHTS = (0.10, 0.55, 1.00, 0.95, 0.70, 0.42, 0.20)`——中间三个八度权重高，
  低音区（被贝斯/鼓占据）和极高区（泛音、噪声）权重低；
- `_smooth_chord_sequence()`：第一次 Viterbi 之后，用「邻居槽位符号占比」做一次平滑，
  消除持续不足 1 拍又反复横跳的符号（与 baseline 在 0.1 s 网格上一致率 0.994，几乎只去抖动）。

## 5. 已知代价（不藏）

**谐波加权让和弦结果更依赖「用哪套分轨」**：跨分轨一致率从 0.966 掉到 0.892（−7.4 点），
同时把平均置信度抬了 0.016、三和弦纯度抬了 1.8 点。换句话说，它让「同分轨内」的打分更干净、
更接近三和弦（这在物理上是对的：基频在八度的能量分布本来就不均匀），但也放大了分轨差异。

处理方式不是装作没这回事：

- 保留 `AITSM_CHORD_HARMONIC=0` 关掉；
- 文档里把「跨分轨一致率下降」写成已知代价；
- **报和弦质量时必须同时报两个指标**（置信度 + 跨分轨一致率），只报置信度会误导。

这与上一轮「重复一致性」实验的教训同形（见 `docs/09-chord-tuning.md`）：**自评置信度升高不等于更真**。

开关一览（都是环境变量，默认值即上文「新默认」）：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `AITSM_RHYTHM_QUANTIZER` | `hmm` | 设为 `grid` 退回旧的就近吸附 |

| `AITSM_CHORD_SMOOTHING` | `1` | 和弦序列平滑 |
| `AITSM_CHORD_FUSION` | `1` | 中值/谱归一化特征融合（见 docs/09） |
| `AITSM_CHORD_REPETITION` | `0` | 重复一致性第二遍（负收益，默认关） |
| `AITSM_MELODY_TRIPLETS` | `0` | 允许旋律落在 1/3 拍网格（默认关，见 §7） |

## 7. 旋律网格：默认只走二分网格，三连音改为显式开关

离线 A/B 之后发现还有一个「算法对了但链路上不对」的地方：`aitsm/score/arrange.py` 的
`_quantize_melody()` 原来把旋律位置吸到 **1/4 或 1/3 网格（三连音优先）**。但下游并不支持三连音：

- 网页渲染器（`web/js/renderer.js`）遇到 1/6 拍这类时值会打出
  `小节 22 时值无法精确记谱：0.1667 拍，用 16`，然后硬吸到十六分音符；
- MusicXML 导出层为了通过 MuseScore 严格导入，已经把三连音改成节奏吸附（见 `docs/04-known-issues.md` #23）。

也就是说：上游安排了三连音，下游默默改写成别的时值——乐谱和实际演唱不一致。改法：

- `_quantize_melody()` **默认只吸 1/4 拍网格**；
- 需要三连音时设 `AITSM_MELODY_TRIPLETS=1`，此时保持精确的 `"1/3"` 分数字符串；
- 新增回归测试 `test_triplet_is_snapped_to_binary_grid_by_default`（默认不出现 `x/3` 时值、位置都在 1/4 网格上），
  原来的三连音测试改为在开关打开后验证。

修完的结果：`work/accept-v4/score.json` 的 413 个旋律音 **100% 落在 1/4 拍网格**，
网页控制台**零告警**（改动前每个小节都会有「时值无法精确记谱」）。

## 10. 尚未解决

- **和弦置信度仍然只有 0.58**。这轮把它抬了 0.01，属于噪声级别的改善——
  和弦识别要靠**自学习字典 / NMF 分解**这类手段，不是调参数能解决的（下一步计划，见 `docs/09-chord-tuning.md` 末尾）。
- **跨分轨一致率下降**（0.966 → 0.892）是谐波加权的已知代价，已在上文 §5 记录。
- 三连音目前等于「关掉」，真正需要三连音的曲风（swing、jazz）会被拉平成二分网格；
  要支持就得让渲染器与导出层都真正支持 tuplet，工作量不小。
